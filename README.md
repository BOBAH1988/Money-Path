# Денежный путь (Money-Path)

PWA для учёта личных финансов, планирования бюджета и анализа расходов. Работает офлайн, синхронизирует данные между устройствами через Firebase, поддерживает светлую и тёмную тему.

**Статус:** активная разработка  
**Страница бюджета:** `/budget`  
**Демо (GitHub Pages):** `https://BOBAH1988.github.io/Money-Path/`  
**Текущая версия:** см. `package.json`

---

## О проекте

Денежный путь — клиентское финансовое приложение с нулевой бэкенд-инфраструктурой со стороны пользователя. Данные гостя хранятся в браузере; данные аккаунта кэшируются локально и синхронизируются с Firestore. Интерфейс адаптирован под мобильные устройства (PWA, нижняя навигация, верхняя панель) и десктоп.

### Синхронизация данных между устройствами
- Firebase Auth запускается при старте, Firestore загружается по требованию. Начальный интерфейс не ждёт загрузки Firestore.
- Данные сначала сохраняются на устройстве. Каждое изменение аккаунта (добавление, правка, удаление и очистка) записывается в устойчивую локальную очередь до отправки в Firestore.
- При входе и восстановлении соединения очередь отправляется по одному аккаунту. Неотправленные операции и удаления остаются в очереди после ошибки; приложение не подменяет сетевую ошибку пустой коллекцией.
- Изменения разных записей объединяются; если несколько устройств одновременно меняют одну запись, применяется последнее синхронизированное изменение этой записи.
- Ошибки синхронизации показываются в интерфейсе, а подробности записываются в консоль браузера с префиксом `[firestore]`.

### Логирование ошибок
- Всё взаимодействие с Firestore логируется через `console.error` с префиксом `[firestore]`:
  - `[firestore] saveToFirestore(...) ошибка:` — сохранение коллекции (активы, пассивы, доходы, архив или плана бюджета).
  - `[firestore] loadFromFirestore(...) ошибка:` — загрузка коллекции.
  - `[firestore] syncPendingToFirestore(...) ошибка:` — отправка ожидающих изменений и удалений.
  - `[auth] login/register/logout ошибка:` — ошибки Firebase Auth.
- При локальной разработке ошибки и стек-трейсы выводятся в консоль DevTools.
- Результаты разбора аудита production-зависимостей и границы применимости найденных advisory: [`docs/security.md`](docs/security.md).
- Процедуры деплоя, мониторинга Firebase и восстановления: [`docs/operations.md`](docs/operations.md).

### Основные возможности
- **Планирование бюджета** — ежемесячные и дополнительные расходы с планом/фактом, автосчёт итогов.
- **Активы и пассивы** — учёт имущества и долгов, дивиденды и проценты в месяц.
- **Доходы и архив доходов** — текущий доход, средний доход по архиву за 12 месяцев.
- **Дашборд** — сводка доходов/расходов, графики, сравнение с планом, оценка баланса.
- **Импорт/экспорт** — выгрузка и загрузка данных в JSON с разрешением конфликтов.
- **Авторизация** — Firebase Auth (email/пароль), восстановление пароля, подтверждение почты, роли (администратор → аналитика пользователей).
- **PWA** — установка на главный экран, Service Worker, офлайн-режим.
- **Темизация** — светлая/тёмная тема, выбор сохраняется в `localStorage`, реагирует на `prefers-color-scheme`.
- **Быстрая загрузка и офлайн-устойчивость** — локальные данные и оболочка PWA доступны без сети; Firestore загружается по требованию, изменения ожидают синхронизации в локальной очереди. Гостевой режим использует локальное хранилище этого устройства.

## Страницы приложения

| Путь | Описание |
|------|----------|
| `/` | Главная (дашборд) |
| `/budget` | Планирование бюджета — ежемесячные + дополнительные расходы |
| `/assets` | Активы |
| `/liabilities` | Пассивы |
| `/income` | Доходы |
| `/income-archive` | Доходы архив (по месяцам, средний доход) |
| `/import` | Импорт/экспорт данных (открывает ImportModal из меню) |

### Страница бюджета (`/budget`)
Две таблицы через общий компонент `BudgetTable`:
1. **Ежемесячные расходы** — фиксированные траты (ипотека, продукты, связь и т.д.)
2. **Дополнительные расходы** — разовые и плановые траты (развлечения, кредитка, буфер и т.д.)

**Действия:** редактирование строки (`✎`), добавление (`+`), удаление (`×` с подтверждением), свёртка/развёртка дополнительных расходов, сброс к стандартным значениям.

**Автосохранение:** изменения сначала сохраняются в локальный кэш и очередь синхронизации, затем отправляются в Firestore. При сбое или отсутствии сети операции, включая удаления и пустой план, остаются в очереди и повторяются при следующем подключении. Гостевой план также хранится локально.

### Главная страница (Дашборд, `/`)

Показывает сводку по доходам, расходам, активам и пассивам за выбранный период: средний доход, плановый доход, общие и регулярные расходы, итого по активам и пассивам, линейную диаграмму доходов и столбчатую диаграмму расходов.

**Пустое состояние:** если данных нет (все суммы нулевые — нет доходов, расходов, активов, пассивов), вместо пустой сводки с нулями показывается подсказка «Нет данных для визуализации» с кнопкой «Перейти к доходам», которая ведёт на страницу `/income` для заполнения данных.

**Настройка периода:** выбор месяца/года через `YearMonthPicker` пересчитывает все сводки и графики под выбранный период.

**Кнопка «Очистить»:** удаляет данные на устройстве и в аккаунте. Если сети нет, очистка ставится в очередь; при последующей загрузке данные не подменяются старой серверной копией до обработки очереди.

## Авторизация и аккаунт

Кнопка «Аккаунт» (👤) в верхней панели:
- **Не авторизован:** открывает окно входа/регистрации (email + пароль), восстановление пароля, подтверждение почты.
- **Авторизован:** меню аккаунта — email, роль (Администратор для `79042044926@ya.ru`), выход, аналитика (только админ).

Требования к паролю: минимум 8 символов, заглавная, строчная, цифра.

Аналитика администратора: всего пользователей, активных, новых за 30 и 7 дней. Для полной аналитики (список всех пользователей) в Firestore Rules нужен `list` коллекции `users` для администратора (см. `firestore.rules`). При правилах «только свой документ» приложение показывает аналитику по вашему аккаунту.

## Синхронизация между устройствами

Данные хранятся в Firestore по пути `users/{userId}/{collection}`. Правила безопасности ограничивают доступ — пользователь видит и редактирует только свои данные. Административная аналитика читает документы `users` и требует отдельного разрешения в правилах.

Чтобы включить синхронизацию:
1. Firebase Console → Authentication → включить **Email/Password**.
2. Firestore → Rules → опубликовать правила (рекомендуемый вариант — `firestore.rules` из репозитория). Правила должны ограничивать доступ данными владельца по `userId`; для полной вкладки «Аналитика» по всем пользователям администратору нужен `list` по `users`.
3. Войти в приложение — новые изменения сохраняются в локальную очередь до отправки; при недоступности сети очередь повторно отправляется при следующем подключении. Удаления также синхронизируются.

## Импорт / экспорт данных

- **Экспорт** — создаёт архив JSON со всеми коллекциями пользователя (активы, пассивы, доходы, архив доходов, план бюджета). Для облачных данных требуется вход в аккаунт.
- **Импорт** — восстанавливает данные из архива. В авторизованном режиме данные записываются в аккаунт/Firestore; в гостевом режиме локально восстанавливаются коллекции и план бюджета в `localStorage` этого браузера. Перед импортом можно очистить локальные данные (актуально для гостевого режима). Записи с совпадающими `id` обновляются данными из архива.

## Доступность (a11y) и клавиатурная навигация

- Все модальные окна закрываются по клавише `Esc`.
- В модальных окнах действует ловушка фокуса (`Tab` циклится внутри окна); при закрытии фокус возвращается на элемент, который открыл окно.
- Прокрутка тела страницы блокируется пока открыто модальное окно.
- Модальные окна имеют `role="dialog"` и `aria-modal="true"`.
- Кнопки темы, навигации и действия помечены `aria-label`.

## Темизация (светлая / тёмная)

Реализована централизованно через CSS-переменные в `src/index.css`:
- Дизайн-токены `--dp-*` (цвета, фоны, границы, тени, переходы) определены для `:root` (светло) и `.dark` (темно).
- Обратная совместимость через `--theme-*`.
- Бюджетные токены `--bp-*` (карточки, таблицы, поля, кнопки) имеют тёмные значения.
- Переключатель темы в выездном меню; выбор сохраняется в `localStorage` (`denegnyj_put_theme`) и применяется при загрузке с учётом `prefers-color-scheme`.
- При отсутствии явного выбора приложение следует за системной темой в рантайме (`matchMedia`), а выбранная вручную тема имеет приоритет.

Все компоненты (таблицы, карточки, модальные окна, инпуты, кнопки, графики, дашборд) переписаны на theme-переменные и корректно перекрашиваются при смене темы.

## Как запустить проект

### 1. Клонировать репозиторий
```bash
git clone https://github.com/BOBAH1988/Money-Path.git
cd Money-Path
```

### 2. Установить зависимости
```bash
npm install
```
После `npm install` автоматически установится `pre-commit` хук, который увеличивает патч-версию перед каждым коммитом.

### 3. Запустить в режиме разработки
```bash
npm run dev
```
Откройте `http://localhost:5173/`.

### 4. Собрать для продакшена
```bash
npm run build
```
Результат появится в папке `dist/`.

### 5. Предпросмотр сборки локально
```bash
npm run preview
```

### 6. Проверить всё перед коммитом
```bash
npm run check
```
Последовательно запускает: `npm run lint` → `npm test` → `npm run build` (TypeScript + Vite). Если одна проверка упадёт — исправьте ошибку перед коммитом.

Отдельно:
```bash
npm run lint
npm test
npm run build
```

Автотесты покрывают логику бюджета, хуки, компоненты и страницы. Запускаются при каждом коммите и на GitHub Actions.

Проект настроен для автоматического деплоя через GitHub Actions.

4. Нажмите **Save**.

| Часть версии | Кто меняет | Когда |
|-------------|------------|-------|

## Основные ошибчи и способы исправления

| Ошибка | Причина | Как исправить |
|--------|---------|---------------|
| `index.html` не открывается при двойном клике | Vite-проект, требует сервер/сборку | `npm run dev` или `npm run build` → `dist/index.html` |
| Белый экран на GitHub Pages | Неверный `base` в `vite.config.ts` | Укажите `base: '/Money-Path/'` |
| Сборка падает в GitHub Actions | Проверьте согласованность `package.json` и lock-файла | В `deploy.yml` зависимости устанавливаются командой `npm ci` |
| Версия не увеличивается при коммите | pre-commit хук не установлен | Запустите `npm install` (сработает `prepare`) |
| Стили не применяются | Кэш браузера | Жёсткая перезагрузка: `Ctrl + F5` / `Cmd + Shift + R` |
| Данные не синхронизируются между устройствами | Firebase не настроен | Включите Email/Password, настройте правила Firestore, войдите в аккаунт |
| Пустой экран / кнопки не работают | AuthProvider блокировал рендеринг до ответа Firebase | Режим гостя работает сразу; Firebase подгружается асинхронно |
| Таблицы пусты без входа | `loadFromFirestore` без `userId` возвращал `[]` | Данные загружаются из `localStorage` без `userId` (режим гостя) |
| Итого не пересчитывается после редактирования | `groupTotal` замирал на старом `plan` из замыкания | `useMemo` напрямую из актуальных `items` |
| Кнопка удаления не работает в режиме редактирования | В `BudgetRow` не было кнопки удаления | Добавлена кнопка `🗑️` с диалогом подтверждения |
| Белый экран в онлайне | Firebase не создан в консоли / неверный конфиг | Приложение работает в режиме гостя через `localStorage`; для синхронизации настройте Firebase и войдите |
