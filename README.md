# Денежный путь (Money-Path)

Клиентское PWA-приложение для ведения личных финансов: бюджет, активы, обязательства, доходы и архив. Гостевой режим работает локально; аккаунт Firebase добавляет облачную синхронизацию между устройствами. Интерфейс и локально сохранённые данные доступны без постоянного подключения к сети.

## Возможности

- **Бюджет:** плановые и фактические расходы, ежемесячные и дополнительные категории, автоматический пересчёт итогов.
- **Финансовые записи:** активы, обязательства, доходы и архив доходов.
- **Дашборд:** текущая сводка доходов, расходов, активов и обязательств; регулярные расходы в плане считаются как «План итого» минус план дополнительных расходов. Архив доходов отображается за последний год с данными.
- **Импорт и экспорт:** JSON-архив данных с предварительной проверкой и восстановлением.
- **Работа офлайн:** гостевые данные, локальный кэш аккаунта и очередь неотправленных изменений.
- **Аккаунт:** вход по email и паролю, восстановление доступа, подтверждение email, повторное согласие с актуальными документами и удаление аккаунта.
- **PWA:** установка на устройство, адаптивный интерфейс, светлая и тёмная темы.

## Как устроены хранение и синхронизация

### Гостевой режим

Записи гостя хранятся в `localStorage` текущего браузера и не синхронизируются между устройствами. Для переноса используйте экспорт и импорт архива.

### Аккаунт Firebase

Данные аккаунта хранятся в пользовательских путях Firestore, например `users/{userId}/assets`. Клиент сначала сохраняет изменения локально, затем отправляет их в Firestore. Неотправленные изменения, удаления и очистки остаются в очереди на устройстве до повторной попытки. Загрузка локальных данных не должна ждать завершения фоновой синхронизации.

Конфликт одновременного изменения одной записи на нескольких устройствах разрешается применением последнего успешно синхронизированного изменения этой записи. Это не журнал версий и не автоматическое слияние полей.

При входе существующий пользователь должен получить доступ к серверу для проверки сохранённых версий документов. Если условия использования или уведомление о конфиденциальности обновлены, приложение блокирует работу с аккаунтом до повторного явного согласия либо выхода.

### Удаление аккаунта

Удаление доступно из меню аккаунта, требует повторного ввода пароля и подключения к интернету. Приложение удаляет облачные записи аккаунта и профиль, его локальные данные, затем Firebase Authentication. Если очистка постоянного кэша Firestore или удаление Firebase Authentication завершились ошибкой, интерфейс сообщает об этом; может потребоваться закрыть другие вкладки, перезагрузить страницу и повторить действие. Экспортированные пользователем файлы удаляются отдельно.

## Локальная разработка

Требуются Node.js и npm. Используйте поддерживаемую проектом версию Node.js, указанную в CI (`.github/workflows/deploy.yml`).

```bash
git clone https://github.com/BOBAH1988/Money-Path.git
cd Money-Path
npm ci
npm run dev
```

Локальный сервер Vite напечатает адрес приложения, обычно `http://localhost:5173/`.

### Команды

| Команда | Назначение |
|---|---|
| `npm run dev` | Запустить сервер разработки |
| `npm run lint` | Запустить oxlint |
| `npm test` | Запустить unit- и компонентные тесты |
| `npm run build` | Проверить TypeScript и собрать приложение |
| `npm run check` | Последовательно выполнить lint, тесты и production-сборку |
| `npm run preview` | Локально просмотреть production-сборку |

Перед публикацией запустите `npm run check`. Тесты Firestore Rules без эмулятора пропускаются; для полного набора используйте Firebase CLI и Java 21 или новее:

```bash
npx --yes firebase-tools@14.22.0 emulators:exec \
  --only firestore \
  --project demo-money-path \
  --non-interactive \
  'FIRESTORE_EMULATOR_HOST=127.0.0.1:8080 npm test -- --run rules-tests/firestore.rules.test.ts'
```

Эмулятор использует локальные правила из `firestore.rules` и не должен обращаться к production Firestore.

## Firebase и безопасность

Для разработки и развёртывания Firebase Auth и Firestore должны быть настроены в проекте Firebase. Клиентские параметры конфигурации можно передать через `VITE_FIREBASE_*`; у веб-приложения также есть публичный Firebase API key для fallback, который попадёт в браузерную сборку. Ограничьте его по HTTP referrer и используемым API в Google Cloud Console. Не добавляйте приватные ключи, пароли или service-account credentials в клиентский код.

Правила [`firestore.rules`](firestore.rules) ограничивают доступ к данным владельцем аккаунта; администратор имеет отдельный ограниченный доступ к списку профилей. Перед изменением правил запускайте emulator-тесты. Для production проект и актуальная схема размещения данных описаны в [уведомлении о конфиденциальности](https://BOBAH1988.github.io/Money-Path/#/privacy) и `docs/operations.md`.

Проверки `npm audit` и `npm audit --omit=dev` проходят без уязвимостей. Для транзитивного `@grpc/grpc-js` задан временный scoped override до совместимого обновления Firebase/Firestore; подробности — в [`docs/security.md`](docs/security.md).

## Тестирование и публикация

GitHub Actions выполняет проверки, тесты, production-сборку и тесты Firestore Rules, затем публикует приложение в GitHub Pages. Workflow запускается после push в `main`. Результат и логи доступны на странице [GitHub Actions](https://github.com/BOBAH1988/Money-Path/actions).

Для ручной публикации требуется включённый GitHub Pages с источником **GitHub Actions**. Vite настроен на base path `/Money-Path/`. Не заменяйте его на `/`, пока приложение размещается в подпути GitHub Pages.

Версия хранится в `package.json` в формате `major.minor.patch`. Pre-commit hook автоматически увеличивает patch-часть версии и синхронизирует `package-lock.json`; major/minor меняются вручную при необходимости.

Документированные ключевые дефекты и изменения находятся в [журнале исправлений](docs/incident-log.md). Для текущих проблем синхронизации и восстановления используйте [операционный runbook](docs/operations.md), а сведения об ошибках и командах проверки — ниже.

### Диагностика

- **Запись не синхронизируется:** убедитесь, что пользователь вошёл в нужный аккаунт и устройство подключено к интернету; проверьте сообщение синхронизации и браузерную консоль. Очередь может содержать ожидающие операции. Не очищайте данные сайта до создания и проверки экспорта.
- **После обновления недоступны данные аккаунта:** подключитесь к интернету, чтобы приложение проверило согласие с текущими версиями документов; подтвердите их или выйдите и повторите позже.
- **Нет доступа к Firestore:** проверьте Firebase Auth, конфигурацию проекта и применённые Firestore Rules. Используйте emulator-тесты перед публикацией изменений правил.
- **Пустая страница на GitHub Pages:** проверьте завершение workflow, корректность `base: '/Money-Path/'` и загрузите сайт после очистки браузерного кэша.
- **Приложение впервые не открывается офлайн:** откройте его онлайн, чтобы браузер получил Service Worker и ресурсы, необходимые для офлайн-запуска.
- **Предупреждения аудита зависимостей:** сверяйтесь с `docs/security.md`; не устраняйте advisory принудительным обновлением транзитивного пакета без проверки совместимости Firebase и полного набора тестов.

Не помещайте содержимое финансовых архивов, пароли, токены или персональные данные в issue, логи CI и сообщения об ошибках. При обращении за поддержкой указывайте только версию приложения, commit SHA, браузер, время и очищенный от персональных данных текст ошибки.
