# Денежный путь (Money-Path)

PWA для учёта личных финансов, планирования бюджета и анализа расходов. Работает офлайн, synchronizирует данные между устройствами через Firebase, поддерживает светлую и тёмную тему.

**Статус:** активная разработка  
**Страница бюджета:** `/budget`  
**Демо (GitHub Pages):** `https://BOBAH1988.github.io/Money-Path/`  
**Текущая версия:** `0.0.243` (`package.json`)

---

## О проекте

Денежный путь — клиентское финансовое приложение с нулевой бэкенд-инфраструктурой со стороны пользователя. Все данные хранятся в браузере (`localStorage`) и, при входе в аккаунт, синхронизируются с Firestore. Интерфейс адаптирован под мобильные устройства (PWA, нижняя навигация, верхняя панель) и десктоп.

### Основные возможности
- **Планирование бюджета** — ежемесячные и дополнительные расходы с планом/фактом, автосчёт итогов.
- **Активы и пассивы** — учёт имущества и долгов, дивиденды и проценты в месяц.
- **Доходы и архив доходов** — текущий доход, средний доход по архиву за 12 месяцев.
- **Дашборд** — сводка доходов/расходов, графики, сравнение с планом, оценка баланса.
- **Импорт/экспорт** — выгрузка всех данных в JSON.
- **Авторизация** — Firebase Auth (email/пароль), восстановление пароля, подтверждение почты, роли (администратор → аналитика пользователей).
- **PWA** — установка на главный экран, Service Worker, офлайн-режим.
- **Темизация** — светлая/тёмная тема, выбор сохраняется в `localStorage`, реагирует на `prefers-color-scheme`.

## Страницы приложения

| Путь | Описание |
|------|----------|
| `/` | Главная (дашборд) |
| `/budget` | Планирование бюджета — ежемесячные + дополнительные расходы |
| `/assets` | Активы |
| `/liabilities` | Пассивы |
| `/income` | Доходы |
| `/income-archive` | Доходы архив (по месяцам, средний доход) |
| `/import` | Импорт/экспорт данных (открывает ImportModal из меню) |

### Страница бюджета (`/budget`)
Две таблицы через общий компонент `BudgetTable`:
1. **Ежемесячные расходы** — фиксированные траты (ипотека, продукты, связь и т.д.)
2. **Дополнительные расходы** — разовые и плановые траты (развлечения, кредитка, буфер и т.д.)

**Действия:** редактирование строки (`✎`), добавление (`+`), удаление (`×` с подтверждением), свёртка/развёртка дополнительных расходов, сброс к стандартным значениям.

**Автосохранение:** изменения сохраняются в Firestore под текущим пользователем и дублируются в `localStorage`. Без интернета — чтение/запись в `localStorage`, при восстановлении соединения — синхронизация с Firebase.

## Авторизация и аккаунт

Кнопка «Аккаунт» (👤) в верхней панели:
- **Не авторизован:** открывает окно входа/регистрации (email + пароль), восстановление пароля, подтверждение почты.
- **Авторизован:** меню аккаунта — email, роль (Администратор для `79042044926@ya.ru`), выход, аналитика (только админ).

Требования к паролю: минимум 8 символов, заглавная, строчная, цифра.

Аналитика администратора: всего пользователей, активных, новых за 30 и 7 дней.

## Синхронизация между устройствами

Данные хранятся в Firestore по пути `users/{userId}/{collection}`. Правила безопасности ограничивают доступ — пользователь видит и редактирует только свои данные.

Чтобы включить синхронизацию:
1. Firebase Console → Authentication → включить **Email/Password**.
2. Firestore → Regeln → опубликовать правила доступа по `userId`.
3. Войти в приложение — локальные данные автоматически переедут в Firestore.

## Темизация (светлая / тёмная)

Реализована централизованно через CSS-переменные в `src/index.css`:
- Дизайн-токены `--dp-*` (цвета, фоны, границы, тени, переходы) определены для `:root` (светло) и `.dark` (темно).
- Обратная совместимость через `--theme-*`.
- Бюджетные токены `--bp-*` (карточки, таблицы, поля, кнопки) также имеют тёмные значения.
- Переключатель темы в выездном меню; выбор сохраняется в `localStorage` (`denegnyj_put_theme`) и применяется при загрузке с учётом `prefers-color-scheme`.

Все компоненты (таблицы, карточки, модальные окна, инпуты, кнопки, графики, дашборд) переписаны на theme-переменные и корректно перекрашиваются при смене темы.

## Как запустить проект

### 1. Клонировать репозиторий
```bash
git clone https://github.com/BOBAH1988/Money-Path.git
cd Money-Path
```

### 2. Установить зависимости
```bash
npm install
```
После `npm install` автоматически установится `pre-commit` хук, который увеличивает патч-версию перед каждым коммитом.

### 3. Запустить в режиме разработки
```bash
npm run dev
```
Откройте `http://localhost:5173/`.

### 4. Собрать для продакшена
```bash
npm run build
```
Результат появится в папке `dist/`.

### 5. Предпросмотр сборки локально
```bash
npm run preview
```

### 6. Проверить всё перед коммитом
```bash
npm run check
```
Последовательно запускает: `npm run lint` → `npm test` → `npm run build` (TypeScript + Vite). Если одна проверка упадёт — исправьте ошибку перед коммитом.

Отдельно:
```bash
npm run lint
npm test
npm run build
```

Автотесты покрывают логику бюджета, хуки, компоненты и страницы. Запускаются при каждом коммите и на GitHub Actions.

## Деплой на GitHub Pages

Проект настроен для автоматического деплоя через GitHub Actions.

### Что уже сделано
- `.github/workflows/deploy.yml` — сборка при пуше в `main`.
- `vite.config.ts` — `base: '/Money-Path/'` для корректных путей на GitHub Pages.
- `public/404.html` — fallback для BrowserRouter при обновлении страницы.

### Как включить
1. Откройте репозиторий на GitHub: `https://github.com/BOBAH1988/Money-Path`.
2. **Settings → Pages**.
3. **Build and deployment → Source** → выберите **GitHub Actions**.
4. Нажмите **Save**.

После следующего пуша в `main` сайт будет доступен по адресу:
👉 `https://BOBAH1988.github.io/Money-Path/`

## Основные ошибчи и способы исправления

| Ошибка | Причина | Как исправить |
|--------|---------|---------------|
| `index.html` не открывается при двойном клике | Vite-проект, требует сервер/сборку | `npm run dev` или `npm run build` → `dist/index.html` |
| Белый экран на GitHub Pages | Неверный `base` в `vite.config.ts` | Укажите `base: '/Money-Path/'` |
| Сборка падает в GitHub Actions | `npm ci` строг к `package-lock.json` | В `deploy.yml` используется `npm install` |
| Версия не увеличивается при коммите | pre-commit хук не установлен | Запустите `npm install` (сработает `prepare`) |
| Стили не применяются | Кэш браузера | Жёсткая перезагрузка: `Ctrl + F5` / `Cmd + Shift + R` |
| Данные не синхронизируются между устройствами | Firebase не настроен | Включите Email/Password, настройте правила Firestore, войдите в аккаунт |
| Пустой экран / кнопки не работают | AuthProvider блокировал рендеринг до ответа Firebase | Режим гостя работает сразу; Firebase подгружается асинхронно |
| Таблицы пусты без входа | `loadFromFirestore` без `userId` возвращал `[]` | Данные загружаются из `localStorage` без `userId` (режим гостя) |
| Итого не пересчитывается после редактирования | `groupTotal` замирал на старом `plan` из замыкания | `useMemo` напрямую из актуальных `items` |
| Кнопка удаления не работает в режиме редактирования | В `BudgetRow` не было кнопки удаления | Добавлена кнопка `🗑️` с диалогом подтверждения |
| Белый экран в онлайне | Firebase не создан в консоли / неверный конфиг | Приложение работает в режиме гостя через `localStorage`; для синхронизации настройте Firebase и войдите |
| Кнопка аккаунта не открывает вход без авторизации | `Layout` открывал `AccountMenu` (возвращает `null` без входа) | При клике проверяется `isAuthenticated` — не вошли → `AuthModal`, вошли → `AccountMenu` |
| Данные возвращаются после сброса | `userId` не совпадал (гость vs uid), Firestore не чистился | `userId = user?.uid ?? undefined` везде; `clearCollectionData` чистит ключи всех `userId` в `localStorage` |
| Таблицы и их содержимое не реагируют на смену темы | `budget.css` задавал `--bp-*` только для светлой темы; `--bp-*` не переопределялись в `.dark`; жёсткие hex-цвета во встроенных стилях | `budget.css` переписан на `--theme-*`/`--dp-*`; добавлены тёмные значения `--bp-*` в `.dark`; жёсткие цвета заменены на переменные темы |
