# Денежный путь

Клиентское PWA для личного финансового учёта: бюджет, активы, обязательства, доходы и их архив. Гостевой режим хранит данные на устройстве; аккаунт добавляет синхронизацию через Firebase.

| | |
|---|---|
| **Приложение** | [BOBAH1988.github.io/Money-Path](https://BOBAH1988.github.io/Money-Path/) |
| **Репозиторий** | [BOBAH1988/Money-Path](https://github.com/BOBAH1988/Money-Path) |
| **Стек** | React 19, TypeScript, Vite, Firebase Auth / Firestore |
| **Версия** | `package.json` → `version` |

> Приложение считает и показывает итоги, но не даёт финансовых или инвестиционных рекомендаций. Перед массовым импортом и крупными изменениями создавайте резервную копию.

## Возможности

- **Бюджет** — плановые и фактические расходы, ежемесячные и дополнительные категории, автоматический пересчёт итогов.
- **Активы, обязательства, доходы** — таблицы с правкой значений и названий прямо в ячейке (Enter — сохранить, Escape — отмена), добавление кнопкой «+», удаление кнопкой «−» с подтверждением.
- **Дашборд** — доходы за месяц, средний доход, осталось оплатить и чистый капитал; «Баланс месяца» делит доход месяца на оплаченное и оставшееся, показывая шкалу и процент оплаты; архив доходов по месяцам с выбором года.
- **Импорт и экспорт** — JSON-архив с проверкой перед восстановлением.
- **Офлайн** — локальный кэш, очередь неотправленных изменений, Service Worker и страница «Нет подключения».
- **Аккаунт** — вход по email и паролю, восстановление доступа, подтверждение адреса, удаление аккаунта с 7-дневным периодом отмены.
- **PWA** — установка на устройство, светлая и тёмная темы, проверка обновлений из меню.

### Требования к паролю

При регистрации пароль должен содержать 10–128 символов, заглавную и строчную буквы, цифру, спецсимвол, не входить в список распространённых паролей и не состоять из повторяющегося фрагмента. Проверка выполняется в `src/lib/validation.ts`.

### Хранение и синхронизация

- **Гостевой режим** — записи в `localStorage` браузера, без синхронизации. Перенос — экспорт и импорт архива.
- **Аккаунт** — данные в `users/{uid}/{collection}` Firestore. Изменения сначала сохраняются локально, затем отправляются в облако; неотправленные операции остаются в очереди устройства.
- **Конфликты** — побеждает последнее успешно синхронизированное изменение записи. Это не журнал версий и не слияние полей.
- **Ошибки облака** — красный баннер «Не удалось обновить данные из облака» снимается только после успешного чтения из Firestore.

### Удаление аккаунта

Удаление запрашивается в меню аккаунта и требует повторного ввода пароля, слова «УДАЛИТЬ» и подключения к сети. Запрос ставится в очередь на 7 дней: вход продолжает работать, в меню показывается плашка с датой и кнопкой отмены. По истечении срока данные стираются при следующем входе — отложенного серверного удаления нет, проект рассчитан на бесплатный тариф Firebase.

## Разработка

Требуются Node.js и npm. Рабочая версия — 24 (`.nvmrc`, `.node-version`), её же используют оба workflow; поддерживается 22+.

```bash
git clone https://github.com/BOBAH1988/Money-Path.git
cd Money-Path
npm ci
cp .env.example .env      # заполнить VITE_FIREBASE_*
npm run dev
```

Dev-сервер открывается на `http://localhost:5173/Money-Path/`; корень `/` перенаправляет туда же. Путь задан `base` в `vite.config.ts`.

| Команда | Назначение |
|---|---|
| `npm run dev` | Сервер разработки |
| `npm run lint` | oxlint |
| `npm test` | Unit- и компонентные тесты (тесты правил пропускаются без эмулятора) |
| `npm run build` | Проверка TypeScript и production-сборка |
| `npm run check` | lint → тесты → сборка |
| `npm run preview` | Просмотр production-сборки |

Перед публикацией обязателен `npm run check`. Полный набор тестов правил требует Java 21+ и Firebase CLI:

```bash
npx --yes firebase-tools@14.22.0 emulators:exec \
  --only firestore \
  --project demo-money-path \
  --non-interactive \
  'FIRESTORE_EMULATOR_HOST=127.0.0.1:8080 npm test -- --run rules-tests/firestore.rules.test.ts'
```

Эмулятор использует локальный `firestore.rules` и не обращается к production Firestore.

## Безопасность

**Ключи.** Параметры Firebase передаются через `VITE_FIREBASE_*` (образец — `.env.example`). В исходном коде ключа нет: без `VITE_FIREBASE_API_KEY` приложение сообщает об ошибке конфигурации.

**Свой сервер (в разработке).** `VITE_DATA_BACKEND=api` вместе с `VITE_API_URL` переключает слой данных с Firestore на собственный API; без обоих значений приложение остаётся на Firebase. `VITE_SHADOW_API=1` включает фоновую сверку с API, `VITE_DUAL_WRITE=1` — дублирование записей. Сервер описан в [`server/README.md`](./server/README.md).

**Ограничение ключа.** Ключ веб-приложения публичен и попадает в браузерную сборку, поэтому в Google Cloud Console его ограничивают по HTTP referrer и списку API. Для GitHub Pages нужны оба адреса — `https://<user>.github.io/*` и `https://<user>.github.io/<repo>/*`, иначе вход отклоняется с `auth/requests-from-referer-…-are-blocked`. Пересматривайте ограничения при смене домена.

**Секреты.** Ключ, попавший в коммит, остаётся в истории git и требует перевыпуска. Приватные ключи, пароли и service-account credentials в клиентский код не добавляются.

**Доступ к данным.** [`firestore.rules`](firestore.rules) разрешает владельцу доступ только к `users/{uid}`, администратору — только чтение списка профилей, корневые коллекции закрыты. Правила не каскадные: совпадающие `allow` объединяются по «или». Любое изменение проверяйте emulator-тестами.

**Зависимости.** `npm audit` и `npm audit --omit=dev` проходят без уязвимостей; для транзитивного `@grpc/grpc-js` действует временный scoped override — см. [docs/security.md](docs/security.md).

## Публикация

GitHub Actions выполняет lint, тесты, сборку и тесты правил, затем публикует артефакт в GitHub Pages. Запуск — по push в `main` или вручную: **Actions → Deploy to GitHub Pages → Run workflow**. Ключ передаётся секретом `VITE_FIREBASE_API_KEY`.

Требования: включённый GitHub Pages с источником **GitHub Actions** и `base: '/Money-Path/'` в Vite — приложение размещено в подпути и не работает с `/`.

Версия хранится в `package.json` как `major.minor.patch`. Pre-commit hook увеличивает patch и синхронизирует `package-lock.json`; major/minor меняются вручную.

## Диагностика

| Симптом | Что проверить |
|---|---|
| Вход отклонён, `auth/requests-from-referer-…-are-blocked` | Список сайтов API-ключа в Google Cloud Console |
| Запись не синхронизируется | Аккаунт и сеть, сообщение синхронизации, консоль браузера; не очищать хранилище до проверки экспорта |
| Нет данных аккаунта после обновления | Подключение к сети и перезагрузка — данные подгружаются из Firestore после авторизации |
| Нет доступа к Firestore | Auth, конфигурация проекта, применённые правила; emulator-тесты перед публикацией |
| Пустая страница на GitHub Pages | Статус workflow, `base: '/Money-Path/'`, кэш браузера |
| Нет офлайна при первом запуске | Один онлайн-запуск: до него Service Worker и ресурсы не сохранены |

Не помещайте финансовые данные, пароли и токены в issue, логи CI и сообщения об ошибках. В обращении указывайте версию, commit SHA, браузер, время и текст ошибки без персональных данных.
