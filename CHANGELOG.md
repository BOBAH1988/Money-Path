# Журнал изменений (Changelog)

## [1.1.146] — 19.11.2026

### Добавлено
- Сверка перед переездом `npm run db:compare`: сравнивает Firestore и Postgres по каждому документу и полю, отдельно перечисляет поля без колонки (`--strict` делает их ошибкой).
- Записи о согласии в профиле (`acceptedTermsVersion`, `acceptedPrivacyVersion`, `consentUpdatedAt`) переносятся в Postgres.

### Изменено
- Чтение Firestore для импорта и сверки вынесено в общий модуль `server/src/scripts/firestore-source.ts`.

### Исправлено
- Повторный импорт больше не затирает уже записанные согласия.

## [1.1.145] — 19.11.2026

### Добавлено
- Периметр серверного API: CORS только для origin из `CORS_ORIGINS`, лимит запросов на uid/IP (`RATE_LIMIT_MAX`, ответ `429`), ограничение размера тела (`BODY_LIMIT`, ответ `413`), заголовки безопасности `@fastify/helmet`.
- Кэш проверки ID-token (`TOKEN_CACHE_TTL_MS`): убирает поход к Google на каждый запрос; плата — задержка отзыва сессии до истечения TTL.
- План полного ухода от сервисов Google — этап 8 в `server/PLAN.md` (свой auth, письма, перенос паролей).

### Изменено
- Маршруты сервера регистрируются внутри `app.after()`: иначе плагин лимитов не навешивает обработчики и лимиты молча не работают.

### Исправлено
- Предварительный `OPTIONS`-запрос браузера больше не получает `401`.

## [1.1.143] — 19.11.2026

### Добавлено
- Сервер `server/`: Fastify + Postgres, маршруты коллекций, плана бюджета, профиля, `sync` одной транзакцией и админская аналитика `GET /admin/stats` (только агрегаты).
- Слой данных переведён на фасад `src/lib/firestore.ts`: транспорт выбирается флагом `VITE_DATA_BACKEND`, добавлены shadow-чтения и dual-write под отдельными флагами.
- Скрипты перед переездом: полный снимок Firestore (`snapshot-firestore.ts`) и живая проверка авторизации (`verify-live-auth.ts`).

### Изменено
- Окно аналитики получает с сервера счётчики вместо чтения всей коллекции пользователей.
- Рабочая версия Node — 24 (`.nvmrc`, `.node-version`, оба workflow).
- Ошибки API показываются понятным текстом (`src/lib/api-errors.ts`).

### Исправлено
- `DELETE` без тела с заголовком `application/json` больше не отвечает 400.
- Интеграционные тесты сервера не вычищают данные друг друга (последовательный запуск файлов).

## [1.1.120] — 18.11.2026

### Изменено
- Убран пункт «Инструкция» из навигации в футере; маршрут `/guide` сохранён и по-прежнему открывается по прямой ссылке.
- Страницы «Условия использования» и «Уведомление о конфиденциальности» получили кнопку закрытия «×» в правом верхнем углу с возвратом на предыдущую страницу.
- README синхронизирован с текущей настройкой: параметры Firebase передаются через `.env`, ограничение ключа по HTTP referrer требует и корня домена, и подпути репозитория, деплой можно запускать вручную через **Run workflow**.
- Запуск деплоя вручную: в workflow добавлен `workflow_dispatch`, кнопка **Run workflow** появляется на вкладке Actions.

### Удалено
- Неиспользуемая зависимость `firebase-admin` из devDependencies.
- Зашитый в `src/lib/firebase.ts` ключ Firebase: теперь он приходит только из `VITE_FIREBASE_API_KEY`, при отсутствии показывается ошибка конфигурации. Утёкший ключ отозван в Google Cloud, история git очищена, ветки Dependabot со старыми коммитами удалены.

### Исправлено
- Вход отклонялся с `auth/requests-from-referer-…-are-blocked`, если в ограничениях ключа не было корня домена `https://<user>.github.io/*` — список сайтов ключа дополнен.
- Добавлен комментарий к глобальному правилу `match /{document=**}` в `firestore.rules`: оно не каскадное и не перекрывает доступ владельцам `users/{userId}`.

## [Не выпущено]

### Исправлено
- «Проверить обновления» действительно проверяет service worker: при найденном обновлении страница перезагружается, без обновления показывается «Обновлений нет», без service worker — честное сообщение вместо тихого тоста.
- Пункт «Импорт» в боковом меню ведёт на страницу `/import`, как указано в README, и больше не открывает модалку экспорта.
- Экспорт в модалке импорта использует `downloadBackup`: файл сохраняется там, где раньше программный клик с мгновенным `revokeObjectURL` игнорировался браузером.
- Верхняя панель и её заголовок используют токены темы — в тёмной теме шапка больше не остаётся белой.
- `theme-color` следует светлой и тёмной теме; `background_color` манифеста приведён к фону приложения.

### Удалено
- Блокирующий запрос повторного согласия с юридическими документами при входе в аккаунт и связанный с ним код: `getLegalConsent`, `recordLegalConsent`, `legalConsentRevision`, стили `.legal-consent-*`.
